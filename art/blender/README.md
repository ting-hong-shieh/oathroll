# Oathroll procedural art

All geometry and materials are original and generated by `oathroll.py` and `skit.py`. No fonts,
numbers, image textures, downloaded models, or external art are used. No external
asset credits are required.

The hero uses an open blank ledger, a sealed vellum card, a vermilion seal with
eight notched spokes, a blank obsidian d20 with gilt seams, a beeswax candle,
and a brass raven-quill holder. A drowned town and bell tower sit outside the
window. The left third is reserved for a title supplied by the game.

## Render

Copy the script with:

```sh
rsync -a oathroll.py partner001:~/solana-build/oathroll-blender/
```

Every invocation must use the shared GPU lock and CPU restrictions:

```sh
ssh partner001 'cd ~/solana-build/oathroll-blender && flock ~/gpu.lock taskset -c 14-15 nice -n 19 ~/solana-build/blender.sh -b -P oathroll.py -- hero'
```

Modes: `preview`, `hero`, `cover`, `seal`, `rest`, `spin`, and `check`. Spin accepts
`--start 1 --end 12` to split the 48 frames into small, serial batches.
`python3 render-queue.py --start 1 --end 48` runs serial four-frame batches;
`--stills` adds the seal pair, resting die, and cover. The queue stops on a
nonzero exit. If interrupted, wait for the remote GPU lock to be released and
inspect existing frames before resuming from the next missing frame.
Use Blender 5.2.3, Cycles CUDA or OptiX, GPU only. The script refuses CPU fallback.
Hero uses 128 samples, studio stills 128, and spin frames 64; all use denoising.
The cover uses a slightly wider lens to keep the moon and sealed card within
its shorter aspect ratio. `cover` rerenders only that asset.

Pull PNGs and timing data with:

```sh
rsync -a partner001:~/solana-build/oathroll-blender/renders/ renders/
```

Pull the four small `.blend` scene files individually from the same remote folder.
Open and review outputs before accepting them. `renders/render-times.jsonl`
records elapsed render time, dimensions, samples, peak process RAM, and sampled
total GPU memory use where NVML is available.

## Web packaging

Run `python3 package-assets.py` with ImageMagick and WebP support installed.
The five stills use quality 85 and preserve alpha. The seamless spin contains
48 distinct phases, at 24 fps on average over exactly two seconds. Frame 49
would equal frame 1; it is deliberately excluded to avoid a pause.

The remote machine has no ffmpeg on PATH, so the loop is an animated WebP.
`final/` contains the six web-ready assets and a byte-size manifest. This is
inside the authorized `art/blender/` boundary. The requested sibling
`art/final/` is outside that boundary; a game integrator can copy these files there.

Transparent assets have no ground plane or baked backdrop. Their RGB lighting
is warm candle gold against a blue moon rim, with blank die facets for UI numerals.
Seal images share one camera, lighting setup, dimensions, and exposure; the
cracked seal is split through all geometry along a jagged fracture.

## Character cold open

`skit.py` builds an original 318-frame, 30 fps, 1920×1080 Keeper/Wren skit,
reusing this pipeline's palette, wax, oak, candle, and blank die helpers.
Modes: `check` saves `skit.blend`; `preview` renders small CPU beat poses;
`frames --start N --end M` writes final PNGs. The final engine defaults to
Cycles CUDA with GPU denoising because headless EEVEE failed its EGL test.

See [skit-notes.md](skit-notes.md) for restrictions, timings, and delivery status.
[skit-edit.json](skit-edit.json) gives exact beat frames and the card's safe
editorial text rectangle at impact. `skit-queue.py` provides eight-frame serial
batches under the GPU lock, systemd memory scope, and cores 14–15. Previews use
CPU only on local core 17. `skit-review.py` validates PNGs and creates contact
sheets and a CPU-encoded review MP4. Full-resolution outputs stay out of Git.
